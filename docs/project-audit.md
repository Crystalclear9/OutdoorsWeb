## 第三轮：后端设计与接口契约

以 `51ae649` 为起点，再由安全、业务和运维三个子代理交叉核对后端，主代理复核需求覆盖及浏览器兼容。

| 确认的不足                                               | 修正                                                                                                                           |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 单条审核、撤回、账号停启用和重置密码的版本检查可省略     | 服务端统一强制最新版本；缺失返回 428，旧版本返回 409；现有测试显式携带实际版本，不在测试助手中自动补齐                         |
| 改期复制图片绕过新申报的磁盘阈值保护                     | 在写事务内、复制前执行相同健康检查；低空间时不新增申请、联系记录、通知或审计，原预约继续保留                                   |
| 排队的审批通知可能在取消、改期或账号停用后发送旧布展指令 | 发送前核对当前预约与收件账号，失效任务关闭并留痕；手机号换绑或退订时继续阻止发送。已结束的批准预约停止旧指令，退回结果保留通知 |

本轮不改变数据库结构。主要需求已有后端实现：真实账号、职责授权、预约及审批、桁架互斥、取消改期、工作日反馈、电话跟进、线下费用、公告、现场登记与运行恢复。真实服务商送达、银行核款和机构人工办理仍按下节验收，不能因为接口测试通过就声明全部运营要求完成。

新增版本契约、改期存储保护、通知有效性共 5 项后端回归，当前 **90 项后端及 45 项浏览器测试通过**，构建与隔离压测通过。没有修改前端产品界面或视觉基线；本轮 Docker/Linux 视觉验证以远程 CI 为准。接口契约收紧后，外部调用方必须先读取最新版本，不能继续省略 `If-Match`。

## 检查范围

- 认证、企业归属、管理员授权、CSRF、来源检查、验证码及 MFA、短信与 OAuth 凭据消费。
- 预约竞争、审批、取消、改期、实际摆放、公告、工作日历、费用状态和通知。
- 备份、恢复、归档、维护租约、离线压缩、异机备份配对及异常收尾。
- 表单互斥、迟到响应、慢网与断网、桌面/手机布局、静态 Pages 未连接状态。
- 构建、全部接口及浏览器回归、固定视觉基线、隔离压测和 npm 依赖审计。实际数量及验证记录见[开发与测试](development.md#验证)。

整套浏览器回归增加后暴露出测试共用来源触发验证码限流的问题；现以测试专用来源隔离解决，正式验证码上限保持不变。失败诊断的共享目录也要求测试进程串行启动，防止诊断文件互相清理。

## 仍需实际环境验收

短信、电话、QQ/微信、S3 与告警仍需服务账号、正确配置和真实联调。收费依据、实际到账、拨号结果和按时反馈由机构及人员核实；系统不会把流水提交或服务商受理当作到账或接通。

当前仍使用单机 SQLite，邮箱所有权和企业真实性尚未核验，未内置完整网络层抗攻击能力。公网须配置 HTTPS、安全 Cookie、持久化密钥和恢复演练。代码审查及自动测试降低已知风险，不能证明不存在其他缺陷。完整边界见[安全文档](security.md)。
