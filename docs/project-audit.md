## 第十一轮：外发通知受理状态与安全重试

在 `3f8d07d` 上由主代理独立复核通知适配器、持久化队列、人工核实和维护恢复。发现服务商所有非成功状态被转成通用 HTTP 503，队列据此自动重试；HTTP 500 即使请求已受理也会重发短信或呼叫。成功响应缺少编号时同样自动重试，非字符串编号反而被当作受理；401/403 反复无效重试，429 则未尊重服务商指定等待时间。

依据 [Twilio 20500](https://www.twilio.com/docs/api/errors/20500) 对非幂等发送的重复风险说明及 [20429](https://www.twilio.com/docs/api/errors/20429) 的明确未处理语义，适配器保留独立的受理不确定、是否可重试及重试时间信息。HTTP 5xx/408 和缺失有效编号进入“需核实”；其他明确客户端拒绝停止自动重试；429 指数退避并等待有效的 `Retry-After`。原有人工核实版本保护、陈旧任务发送前核对及迟到结果审计继续有效。禁止自动重定向，并取消拒绝响应正文。
