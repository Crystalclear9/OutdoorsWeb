# 华中科技大学户外广场企业布展预约系统

第一版前后端实现：React 界面、Node.js 24 API、SQLite 数据库。账号、申请、设计图、审核、公告、场地安排和操作日志全部保存在服务端。不再使用身份切换、本机模拟申请或预置企业数据。

## Docker 启动

需要已启动的 Docker Desktop（Linux containers）或 Docker Engine + Compose。

1. 将 `.env.example` 复制为 `.env`：Windows 执行 `Copy-Item .env.example .env`，Linux/macOS 执行 `cp .env.example .env`。
2. 编辑 `.env`，设置管理员 `ADMIN_EMAIL` 和独立的 `ADMIN_PASSWORD`。密码需为 10–128 位并包含英文字母和数字。程序拒绝示例密码占位符。不要提交 `.env`。
3. 执行：

   ```powershell
   docker compose up --build -d
   ```

4. 访问 **http://localhost:8080**。管理员使用配置的邮箱和密码登录，首次按页面提示开启两步验证并保存恢复码；企业在“登录 / 注册”中创建账号。Docker 默认要求管理员开启两步验证。

数据库和图片保存在 `app-data` 持久卷。重建镜像或 `docker compose down` 不清除数据。请勿使用删除卷的选项，除非已备份且确定要清空业务数据。在 `.env` 设置 `APP_PORT` 可更换访问端口。

```powershell
docker compose ps
docker compose logs --tail=100 app
```

公网运行请配置 HTTPS 反向代理，并设置 `COOKIE_SECURE=true`。默认 HTTP 配置供本机运行。正式服务推荐通过同一域名提供页面与 API。

## 账号与业务

- 企业：注册、登录、退出、资料维护、修改密码；修改密码后全部设备会话失效。
- 验证码：注册和登录均需填写 6 位数字 PNG 图片验证码；点击图片换一张。验证码由服务端生成并绑定浏览器，5 分钟过期，答错或验证成功即作废，不能重复使用；密码或网络错误后前端换图并保留其他输入。图片验证码不代表邮箱、手机号或企业身份已核验。
- 超级管理员：首次由服务端配置创建，拥有全部管理权限；通过“授权管理”创建工作人员并分配独立职责。普通注册只能获得企业身份，无法自行提升权限。
- 工作人员：按需授予企业申请审核、公告管理、场地开放管理、企业账号管理或日志查看权限。界面菜单和 API 使用同一权限定义；没有授权即使直接调用接口也会拒绝。
- 账号恢复：企业账号管理员只能管理企业。超级管理员可管理工作人员，受保护的超级管理员账号不能在网页中降权、停用或重置。临时密码仅显示一次，首次登录强制修改。
- 恢复密码：由管理员核验身份后重置。本版不发送验证邮件，也没有无验证的自助重置入口。
- 申报：最长 3 天（含起止日期）、29 个桁架位、3 MB 以内 JPG/PNG/WebP 设计图；待审核申请可撤回，未通过后可重新申报。
- 审核：查看完整申请与原图，通过/退回，退回原因必填；事务确保冲突时段不能重复通过。
- 取消：在申请详情中填写原因并明确确认，可取消仍生效的已通过预约，立即释放位置。企业只能取消自己的尚未开始或当日开始的预约；已开始但未结束的活动由有审核权限的管理员处理。已结束的预约保留历史，不允许通过取消改写历史。取消必须携带最新版本，不能恢复旧预约。改期请使用独立的“申请改期 / 换位”功能。
- 改期：企业在未开始的生效预约详情中申请改期或换位，沿用原企业资料和设计图。待审期间保留原预约；退回或撤回不影响原预约；批准时在同一事务中取消原预约并批准新预约。原预约取消时，待审改期自动撤回。只允许一份待审改期，所有审批仍检查冲突与版本。
- 现场登记：有场地管理权限的工作人员可在“场地开放安排”逐位登记今天的实际摆放与备注，支持按批准清单预填后核对；历史只读。实际摆放数与批准占位分别显示；批量保存全有或全无，并发冲突提示刷新。
- 审批台：管理员进入“企业申报审核”，默认左侧待办队列、右侧材料审阅。支持搜索、先到先审/最新优先排序、上一条/下一条、通过或退回后自动切换、快捷退回原因；桌面材料独立滚动，操作区始终保留在下方。
- 辅助核对：待审列表和详情提示日期过期、已通过预约冲突、暂停开放，以及同位重叠的其他待审数量。系统只核对日期与占用，设计图内容仍由有审核权限的人员确认。
- 批量处理：勾选本页记录后可批量通过/退回，操作前显示企业、位置、日期及冲突提示，并要求明确确认。统一退回原因必填；版本过期或冲突记录逐条跳过，页面列出成功数量和失败原因。服务端每批最多 50 条，当前列表每页 15 条，选项不跨搜索/分页保留。所有成功记录分别审计；若网络或权限中途异常，应刷新列表核对，重复处理不会覆盖终态。
- 隔离：企业只可查看自己的申请和图片；游客只看到公共场地信息与公告。
- 工作台：企业查看最近申请与审核意见，管理员直接处理待办，并查看最新公告；工作台不重复展示场地图。
- 场地查询：按 PDF 原图的五段位置提供日期查询、分布图/列表、区域筛选和放大查看。绿地边缘 6 个、B 座通道 4 个、A 座通道 4 个、东侧直线 7 个、南侧直线 8 个，共 29 个；已有预约的时段不能关闭。
- 地图比例：默认同时适配容器宽度和屏幕高度，保留原图 1350:1185 的纵横比；工具栏显示相对适配尺寸的缩放比例（75%–300%），支持一键适配、展开查看和 Escape 收起，放大后在地图内滚动。
- 公告：管理员在公告页直接填写标题和正文发布，可置顶，支持 Ctrl+Enter；发布失败保留输入。已发布内容支持编辑和删除，企业与游客公开阅读。
- 消息：工作台提供私有办理消息，显示审批结果、取消通知及待办提醒。提交申请会通知当前有审核权限的管理员；后台维护每天最多生成一次超过 24 小时的待办提醒。支持标记已读和分页。配置通信服务后，可按用户选择向已验证号码发送审批结果短信或自动语音电话。
- 日志：保留账号与业务操作，按日期、邮箱、操作代码或关联编号分页查询，可导出当前页 CSV；日期按北京时间解释。账号管理也改为服务端搜索与分页，不再截断为最近 1000 个账号。

## 并发、权限与会话规则

- **待审核不占位**：多家企业可以申请同一位置，但相同桁架在重叠日期内只能有一条生效预约。起止日期均计算在内；审核通过后占位，待审核申请可以撤回。
- **数据库兜底**：SQLite 触发器同时约束已通过预约、暂停安排和同一企业重复待审核申请。审批、撤回、暂停与恢复均在写事务中完成，并在事务内重新读取状态与授权；多进程共享同一个数据库文件也不能重复占用。
- **重试防重复**：提交申请支持 `Idempotency-Key`，同一账号以同一标识重试相同内容会得到原申请编号，不会新增记录或重复审计。同一标识提交不同内容返回 409。前端失败重试自动复用标识，修改内容后生成新标识。
- 幂等记录有效期为 7 天，后台会清理更早的标识；7 天后旧标识不再保证返回原编号，预约状态、重复待办和占用约束仍继续有效。
- **过期页面保护**：申请详情含版本号，前端审核和撤回携带 `If-Match`。状态已变化时返回 409，详情会重新读取。公告编辑/删除及管理员授权必须携带最新 `If-Match`，缺失返回 428，版本冲突返回 409，避免覆盖他人修改。
- **写入时重新鉴权**：不能使用上传开始时缓存的身份决定最终写入权限。停用、密码重置、退出或授权收回后，已失效会话即使继续上传也不能完成写入。管理员不能审批自己提交的申请。
- **授权确认**：创建工作人员、调整授权需超级管理员再次填写自己的当前密码。收回或调整权限会撤销目标账号全部登录会话，重新登录后才使用新权限。授权变更记录包含操作者、目标和权限变更内容，拒绝越权请求也会记录。
- **会话管理**：“账号设置”可查看当前及其他有效登录设备，退出某个其他设备或一次退出其他设备。只能管理自己的会话；修改密码会撤销包括当前设备在内的全部会话。
- **频率限制与失败响应**：注册、登录、密码与授权操作限流由数据库原子计数，超过返回 429。另对账号写请求或未登录来源设置每分钟 120 次的上限。为避免恶意灌日志，同一账号每分钟最多记录 10 条拒绝事件。数据库短时忙碌返回 503 和 `Retry-After`，不把抢锁失败伪装成预约成功。
- **认证资源与异常隔离**：所有密码散列及验证共用每进程最多 2 个运行任务、16 个等待任务的队列；超出返回 503，任务失败仍释放名额。短信验证码及两步验证的五次尝试上限在数据库原子计数或事务内执行，并在消费前重新检查有效期与凭据状态，适用于共享同一本地数据库的多个进程。畸形请求地址返回 400，错误日志使用已解析的安全路径，避免错误处理再次抛错退出服务。

当前 Docker 版适用于单机 SQLite 或多个进程共享**同一个本地数据库文件**。不支持把数据卷复制成多台服务器的独立数据库后继续保证全局互斥，也不建议使用网络文件系统共享 SQLite。多服务器部署需改用支持集中事务的数据库。

升级前请先备份数据库。启动会执行保留业务数据的增量迁移；旧版已有管理员原本拥有完整管理能力，因此保留完整权限并迁移为超级管理员。新建工作人员只能获得明确勾选的权限。

数据库版本现为 6。旧版预约、图片、账号和日志保留，取消信息采用新增字段；取消记录仍关联原申请。程序拒绝高于自身支持版本的数据库。升级后不要直接切回不理解取消状态的旧镜像；回滚必须先停服务、备份当前数据，再使用相匹配的旧数据库与程序版本。升级前发出的手机号绑定验证码须重新获取。

## 长期运行与维护

超级管理员可在“运行维护”查看数据库和磁盘检查、最近成功备份、维护失败信息及超时待办，并手动启动一次后台备份和清理。普通企业及工作人员不能使用维护 API。

- 服务启动约 10 秒后执行首次维护，随后每小时检查一次。默认约每 24 小时备份，保留最近 14 份自动备份；`BACKUP_INTERVAL_HOURS`、`BACKUP_KEEP` 可调整，间隔设为 0 仅关闭自动备份，仍进行清理和手动备份。
- 备份在独立 Node 进程中执行，先写 `.part` 文件，完成 `PRAGMA quick_check` 后才改名为正式备份，并记录成功时间。只轮换本程序生成的 `auto-*.sqlite`，保留数量最少为 2；不会轮换人工命名的备份。失败保留诊断，并输出结构化错误日志。
- 维护页同时核对最近备份文件是否存在；文件丢失或为空会提示异常，并在下次已启用的自动维护中重新生成。复制前检查备份目录可用空间，预留数据库估算大小及安全余量，避免已知空间不足时继续复制。
- 默认目录 `/app/data/backups` 随 Docker 数据卷保留。**这仍是本机备份**，请通过运维任务复制到异机或其他独立存储；已实现 S3 兼容加密异机复制及签名 Webhook 告警，需填写服务凭据后启用，见下文。
- 定期清理过期验证码、过期会话、过期超过一天的限流记录、超过 7 天的幂等标识，以及超过 180 天的已读消息。预约与账号保留。默认超过 365 天的非待审申请设计图及历史审计日志分批完整归档；设计图仍在原申请按权限读取，审计归档在“操作日志”下载 JSONL，读取时校验 SHA-256。
- 设计图仍存于 SQLite；单个企业未归档设计图限制为 200 MB。归档保留在同一个 SQLite 快照中，保证恢复时资料齐全；这是冷热分层，保留的数据仍占用磁盘。新库启用增量空间回收，每次维护最多回收 1024 个空闲页；旧库可离线压缩并启用后续增量回收，见下文。空间回收不删除保留的历史资料，仍需容量规划。`ARCHIVE_AFTER_DAYS` 可设为 30–3650 天，每次维护最多归档 20 张历史图片及 2000 条旧日志。磁盘可用空间低于 `MIN_FREE_DISK_MB`（默认 256 MB）时，健康检查失败并阻止继续提交申请；不能代替磁盘容量规划。
- `/api/health` 检查数据库写入能力及磁盘空间，异常返回 503，不公开内部路径。反向代理或外部监控可检测这个地址；Docker Compose 的应用日志限制为每份 10 MB、最多 3 份。健康失败不会自动等同于完成修复，需要维护人员处理。
- 异常请求日志含 `X-Request-ID` 对应编号，方便定位；不输出请求正文和密码。界面中的维护状态与站内消息不能代替独立于应用的故障告警。

反向代理部署时，将 **直接连接应用、且确实由你控制的代理 IP** 填入 `TRUSTED_PROXY_IPS`（逗号分隔），代理应正确覆盖或追加 `X-Forwarded-For`。程序从右向左跳过可信代理，取第一个非可信地址；未配置时忽略所有转发头。不要信任任意用户能控制的代理或整个公网，否则会破坏限流。代理容器更换 IP 后，应同步更新配置。

注册和登录 API 调用需先获取 `/api/auth/captcha`，保留响应的 `hust_captcha` Cookie，将返回的 `id` 作为 `captchaId`、用户输入作为 `captcha` 一起提交。验证码答案只以摘要保存，响应不含明文答案。测试通过 `createApp` 的内部依赖注入生成固定测试图片；正式入口及环境变量没有免验证码开关。

邮箱是登录名，**本版不验证邮箱所有权**。手机号可在账号设置中通过短信验证码及当前密码绑定，绑定后可用于快捷登录与本人选择的结果通知；资料中的联系电话不自动视为已验证号码。首次短信、QQ/微信验证后，可补齐企业资料并创建企业账号；已有邮箱账号须先登录后绑定，不按第三方昵称或相同邮箱自动合并。注册凭据绑定当前浏览器、10 分钟过期且单次消费；并发重复提交只会创建一个企业账号，客户端不能指定管理员身份。审核结果以系统申请记录为准。

手机号绑定验证码同时关联发起绑定的账号，切换账号不能消费；密码验证完成后在写入事务内再次检查有效期、尝试次数和归属。快捷注册凭据过期时保留当前填写内容并提示重新验证。登录完成后，旧会话查询或旧账号请求的迟到响应不能覆盖新登录状态。

已补齐现场实际摆放登记、保留旧预约的改期审批、图片完整解码、历史资料归档和管理员两步验证。短信、QQ/微信、自动电话、S3 与外部告警均有真实服务接口，但第三方账号申请、区域开通、域名回调与实际送达仍需使用自己的服务账号验收。测试注入的通信响应不代表真实运营商、QQ、微信或对象存储已接通。

场地底图来自需求 PDF 第 11 页的原图区域（第 26 页同图），以 1350×1185 像素保存于 `src/assets/venue-plan.png`。交互坐标逐个对齐原图桁架，位于 `src/venue-layout.js`；不再重新编造布局或套用 9/10/10 分区。A 座、B 座是建筑名，原图未提供桁架编号，页面改用中性的 01–29 号作为系统编号，数据库 slot 主键保持不变，已有申请或暂停安排仍保留关联。具体位置以现场为准。

## 本地开发

### 两步验证与密钥

账号设置支持扫码绑定 TOTP 验证器，确认动态码后才启用，并显示 10 个一次性恢复码。登录先验证密码，再验证动态码或恢复码；验证码不可重放，挑战绑定当前浏览器、5 分钟有效、最多 5 次尝试。启用或关闭时撤销其他设备会话。Docker 默认 `REQUIRE_ADMIN_MFA=true`，未登记的管理员只能完成账号安全设置；现有安装升级后也需登记。

密钥以 AES-256-GCM 加密保存。`APP_ENCRYPTION_KEY` 是可选的 64 位十六进制密钥；未设置时自动生成 `/app/data/.mfa-key`，不得删除、随意更换或提交到 Git。可用 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 在本机生成密钥。恢复码请离线保存。

### 短信、语音与 QQ/微信

在 `.env` 配置 `TWILIO_ACCOUNT_SID`、`TWILIO_AUTH_TOKEN`、`TWILIO_FROM`，并在 Twilio 开通目的国家、发送方及相应服务。短信接口与语音调用分别使用 [Messages](https://www.twilio.com/docs/messaging/api/message-resource) 和 [Calls](https://www.twilio.com/docs/voice/api/call-resource)。不同地区的发送资格、模板及费用由服务商管理，配置前登录页不展示未开放的快捷入口。

- 在账号设置验证并绑定手机号。短信发送前要求图片验证码；同号码最多每分钟一次、每天 10 次，同来源每小时 10 次。短信码 5 分钟有效、最多 5 次尝试、绑定浏览器且只能使用一次。绑定另需当前账号密码；同号码只能绑定一个账号。
- 用户在账号设置主动勾选审批结果短信或电话通知；只向已验证号码发送。管理员使用短信登录时也必须完成 TOTP。管理员 QQ/微信登录被禁用，保留密码和两步验证。
- 审批事务只写入发送任务，网络发送每 15 秒在后台处理，不阻塞审批。明确失败指数退避，最多 5 次；网络超时或进程中断的结果标记“需核实”，不自动重复拨打。运行维护页可查看最近 50 条任务并核实、关闭或重试明确失败的任务。受理编号表示服务商受理，不能当作用户实际收到的证明。
- QQ/微信配置 `PUBLIC_URL`、`QQ_CLIENT_ID/QQ_CLIENT_SECRET`、`WECHAT_CLIENT_ID/WECHAT_CLIENT_SECRET`。公共地址通常须为 HTTPS 根地址，例如 `https://venue.example.edu.cn`。在开放平台登记精确回调：`https://venue.example.edu.cn/api/auth/oauth/qq/callback`、`https://venue.example.edu.cn/api/auth/oauth/wechat/callback`。微信使用网站应用扫码登录资质。首次授权后进入企业资料补全页，完成后创建并绑定企业账号；已有账号请先在账号设置中绑定。授权 state 单次消费、10 分钟有效且绑定浏览器。令牌只用于服务端换取 OpenID，不保存到浏览器。

QQ 实现遵循[官方服务端授权流程](https://wiki.connect.qq.com/使用authorization_code获取access_token)，微信入口与回调采用[网站应用登录协议](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)。第三方拒绝授权、超时或未绑定会显示明确错误，重新登录后可重试。

### 加密异机备份、恢复与独立告警

配置 `S3_BACKUP_BUCKET`、区域、凭据及独立的 `BACKUP_ENCRYPTION_KEY`（64 位十六进制）。兼容存储可设置 `S3_BACKUP_ENDPOINT` 与 `S3_PATH_STYLE=true`；端点默认要求 HTTPS，只有受控内网测试才显式设 `S3_ALLOW_HTTP=true`。存储桶须为私有，配置生命周期规则控制异机保留时间，本程序不会删除远端对象。

每份本地快照通过完整性检查后，将数据库及 MFA 密钥一起使用 AES-256-GCM 加密上传，随后 HEAD 检查并下载回读 SHA-256 校验；全部成功才标记“复制并校验成功”。复制失败保留本地备份并在下一次维护重试，维护页显示状态。不要把异机加密密钥仅保存在这台服务器：丢失后无法恢复。文件格式为 `HUSTBK01` + 12 字节 IV + 密文（32 字节 MFA 密钥及 SQLite 文件）+ 16 字节认证标签。

下载 `.sqlite.enc` 后恢复到新目录：

```powershell
npm run restore:encrypted -- ./downloaded.sqlite.enc ./restored/app.sqlite
```

此命令读取 `.env` 中的 `BACKUP_ENCRYPTION_KEY`，验证认证标签及数据库完整性，不覆盖已有数据库；成功后生成 `app.sqlite` 和 `.mfa-key`。每次恢复使用独立临时文件，失败只清理本次临时文件，不删除其他恢复任务的中间文件。启用前将 `DB_PATH` 指向恢复文件；如设置 `APP_ENCRYPTION_KEY`，确保它与备份内原密钥一致。先在隔离环境核验账号、历史图片与 MFA，再按运维流程切换服务。

`ALERT_WEBHOOK_URL` 接收 JSON `{event,detail,at,service}`，支持 `ALERT_WEBHOOK_TOKEN` Bearer 认证和 `ALERT_WEBHOOK_SECRET` 的 HMAC-SHA256 签名（请求头 `X-HUST-Signature`，签名对象为原始请求正文）。健康、维护或发送队列异常会触发告警，同类成功告警抑制 30 分钟。接收方必须校验签名并返回 2xx；接收失败会在维护页显示。此接口适合接入自己的告警网关；企业微信、钉钉等不同消息格式应由网关转换。

应用自身停机时无法自报。另提供独立探测进程，设置 `MONITOR_URL=https://venue.example.edu.cn/api/health` 和上述告警变量，运行 `npm run monitor`。每 30 秒探测，连续失败 3 次告警，恢复后发送恢复事件；单次检查可执行 `npm run monitor -- --once`。应运行在另一台设备或独立监控平台，不能用同一应用容器代替整机故障监控。所有外发服务尚需用户自己的凭据和实际连通性验收。“运行维护”的接入检查逐项显示短信、QQ、微信、S3、告警的缺失配置和地址格式问题，只显示变量名称，不泄漏凭据；配置完整仍标记为待实际联调，不冒充已经验收。

### 压测与视觉回归

## 管理员恢复与备份

管理员在首次启动时创建，后续更改环境变量不会自动覆盖已设置的密码。忘记管理员密码时，先修改 `.env` 的管理员配置，再显式执行：

```powershell
docker compose run --rm app node server/admin.mjs
```

该操作更新管理员密码并撤销其全部会话，不会把已注册企业提升为管理员。非 Docker 环境执行 `npm run admin:recover`。验证器与全部恢复码同时遗失时，仅由有服务器权限的运维显式执行 `node server/admin.mjs --reset-mfa`（或 `npm run admin:recover -- --reset-mfa`），重置后管理员必须重新扫码。普通密码恢复不会移除 MFA。

在线一致性备份：

```powershell
docker compose exec app node server/backup.mjs /app/data/backups/manual.sqlite
docker compose cp app:/app/data/backups/manual.sqlite ./backup.sqlite
docker compose cp app:/app/data/backups/manual.sqlite.mfa-key ./backup.sqlite.mfa-key
```

备份使用 SQLite `VACUUM INTO`，包含账号、申请、图片、归档及通知队列。旁边的 `.mfa-key` 也必须保管，恢复时作为数据库同目录的 `.mfa-key`；使用 `APP_ENCRYPTION_KEY` 时保留同一密钥。备份和密钥均为敏感资料，限制访问。目标文件必须尚不存在，每次备份请更换文件名。不要仅复制运行中的 SQLite 主文件，WAL 中可能仍有未合并数据。

恢复前先停止应用并备份原卷。由运维人员通过临时容器替换卷内数据库，并处理相应 WAL/SHM 文件后再启动。不要将任何业务数据库提交到仓库。

### 旧库离线压缩与空间回收

在维护窗口先停止应用，再执行以下命令。程序会先检查数据库及临时磁盘空间，生成 `precompact-*.sqlite` 安全快照和 MFA 密钥副本，校验成功后才重建数据库并启用增量回收；不删除预约、图片、账号或历史归档。保留安全快照直到确认运行正常。大库需预留额外空间，空间不足会拒绝执行。

```powershell
docker compose stop app
docker compose run --rm app node server/compact.mjs --offline
docker compose up -d
```

非 Docker 环境停止 Node 服务后运行 `npm run compact -- --offline`。维护页显示已分配空间、可复用空间以及是否启用增量回收。依据 [SQLite 空间回收机制](https://www.sqlite.org/pragma.html#pragma_auto_vacuum)，旧库由 NONE 模式切换需一次 VACUUM；程序不会在升级启动时自动执行可能长时间阻塞的大库重建。

## GitHub Pages

https://crystalclear9.github.io/OutdoorsWeb/ 保留为静态前端入口。**Pages 不能运行 Node.js API 或数据库，无法独立提供真实账号服务。** 未连接后端时，页面明确提示、禁用申请提交，不显示模拟占用数据。账号及业务操作请使用 Docker 完整服务地址。

`npm run build` 生成 `dist/`，并将编译后的 `index.html` 和 `assets/` 同步至仓库根目录，适配目前 `main / (root)` 的 Pages 发布设置。源入口为 `src/index.html`，静态资源使用相对路径，兼容 `/OutdoorsWeb/`。

`VITE_API_BASE_URL` 可在编译时指定 API 地址，但推荐 Docker 同域运行。会话 Cookie 使用 SameSite=Lax，不能把跨站 Pages + API 直接视为正式同域服务。

## 项目结构

- `src/`：React 界面，Radix Dialog 提供焦点和键盘交互。
- `server/`：HTTP API、SQLite、密码与会话、备份和管理员恢复。
- `shared/permissions.js`：前后端共用的业务权限定义。
- `server/tests/`：接口与权限测试。
- `tests/`：浏览器和静态发布测试。
- `Dockerfile`、`compose.yaml`：非 root 容器、健康检查、持久卷。

密码使用随机盐 scrypt 哈希；HttpOnly Cookie 会话令牌在数据库中仅保存摘要。认证写入检查来源与 CSRF。登录和注册设有频率限制，图片除文件头校验外，使用 sharp 完整解码，拒绝动画、最长边超过 10000 或超过 2000 万像素的图片；剥离元数据并重编码为无损 WebP，输出上限 6 MB。每进程最多同时解码 2 张、排队 16 张，超额返回 503，可按原幂等标识重试。实际使用时请根据校方要求完成域名、HTTPS、备份、隐私告知与运维配置。
