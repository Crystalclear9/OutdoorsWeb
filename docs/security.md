# 防御措施、权限与账号安全

本文依据当前代码整理，更新日期为 2026-10-22。项目具备应用层鉴权、输入与资源约束、业务一致性和故障恢复保护；这些措施不等于网络层防护或生产环境已经验收。

公共场地接口的现场记录仅包含位置、摆放状态与更新时间，不公开现场备注、操作者或版本；未登记与已登记未摆放明确区分。访问二维码仅编码当前来源和路径，去掉查询参数及片段，避免把回调或验证信息带入分享地址。

## 防护概览

当前 Pages 临时成果演示仅在专用构建与指定静态入口启用，展示身份和虚构数据保存在当前标签页，不设置认证 Cookie、不连接或回退到真实 API。正常构建不输出此运行模块，URL 参数和存储不能开启演示身份。它不构成身份核验或后台授权，正式启用前按[待删除清单](temporary-showcase.md)移除。

| 风险                       | 当前实现                                                        | 代码位置                                                          |
| -------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------- |
| 密码泄露、反复猜测         | 随机盐 scrypt、图片验证码、数据库限流；支持 TOTP 与一次性恢复码 | `server/security.mjs`、`captcha.mjs`、`mfa.mjs`                   |
| 会话盗用与跨站写入         | HttpOnly / SameSite Cookie、令牌摘要、来源检查与 CSRF 校验      | `server/core.mjs`、`app.mjs`                                      |

## HTTP 与资源边界

Node 完整服务检查 API 请求来源，认证写入要求 CSRF Token；同域访问通常不需要额外来源配置。公开只读接口不以 CSRF Token 作为访问条件，不能把 CSRF 校验当作身份认证。`PUBLIC_ORIGIN` 只允许明确配置的额外来源；代理来源识别仅信任 `TRUSTED_PROXY_IPS` 中的精确地址，忽略非可信连接伪造的转发头。

完整服务设置 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和同源 Referrer 策略，API 响应禁止缓存。静态页面设置 CSP，将脚本和连接限制在同源，禁止对象嵌入及页面被嵌套；样式仍允许内联，图片允许 data/blob。上述响应头由 Node 服务设置，GitHub Pages 不自动继承它们。

静态文件限制在构建目录和允许的文件类型内；业务查询使用参数绑定。JSON 请求体最大 4,500,000 字节，上传图片本身最大 3 MiB；两者不同是因为图片在 JSON 中使用 Base64 传输。HTTP 请求接收超时为 30 秒，请求头超时为 15 秒，不代表所有后台业务都能在该时间内完成。畸形地址返回 400，内部错误对外使用通用提示，不直接返回堆栈。

| 限制项                            | 当前上限                                                  |
| --------------------------------- | --------------------------------------------------------- |
| 普通注册                          | 同来源每小时 10 次                                        |
| 密码登录                          | 同来源每 15 分钟 60 次；同账号每 15 分钟 10 次计数        |
| 生成图片验证码                    | 同来源每 10 分钟 60 次                                    |
| 认证账号写请求 / 未登录来源写请求 | 每分钟 120 次                                             |
| 密码散列与验证                    | 每进程 2 个运行任务、16 个等待任务                        |
| 图片完整解码                      | 每进程 2 个运行任务、16 个等待任务                        |
| 设计图输入                        | 3 MiB、静态 PNG/JPEG/WebP、最长边 10000、最多 2000 万像素 |
| 图像重新编码输出                  | 最大 6 MiB，剥离元数据的无损 WebP                         |

不同限制独立生效；密码验证成功后清除对应账号的登录计数，限流不是永久封号。超频返回 429，计算排队溢出或数据库忙碌返回 503。并发上限按进程计算，不能推算成整台服务器或网络的统一容量保证。

## 并发、权限与会话规则

- **待审核不占位**：多家企业可以申请同一位置，但相同桁架在重叠日期内只能有一条生效预约。起止日期均计算在内；审核通过后占位，待审核申请可以撤回。
- **数据库兜底**：SQLite 触发器同时约束已通过预约、暂停安排和同一企业重复待审核申请。审批、撤回、暂停与恢复均在写事务中完成，并在事务内重新读取状态与授权；多进程共享同一个数据库文件也不能重复占用。
- **重试防重复**：提交申请支持 `Idempotency-Key`，同一账号以同一标识重试相同内容会得到原申请编号，不会新增记录或重复审计。同一标识提交不同内容返回 409。前端失败重试自动复用标识，修改内容后生成新标识。
- 幂等记录有效期为 7 天，后台会清理更早的标识；7 天后旧标识不再保证返回原编号，预约状态、重复待办和占用约束仍继续有效。
- **过期页面保护**：单条审核、撤回、取消、改期、账号停启用及密码重置必须携带最新 `If-Match`；批量审批每条必须携带版本。公告编辑/删除及管理员授权也必须携带最新版本，缺失返回 428，版本冲突返回 409，避免绕过界面保护覆盖他人修改。业务状态检查和事务互斥仍同时生效。
- **写入时重新鉴权**：不能使用上传开始时缓存的身份决定最终写入权限。停用、密码重置、退出或授权收回后，已失效会话即使继续上传也不能完成写入。管理员不能审批自己提交的申请。
- **授权确认**：创建工作人员、调整授权需超级管理员再次填写自己的当前密码。收回或调整权限会撤销目标账号全部登录会话，重新登录后才使用新权限。授权变更记录包含操作者、目标和权限变更内容，拒绝越权请求也会记录。
- **会话管理**：“账号设置”可查看当前及其他有效登录设备，退出某个其他设备或一次退出其他设备。只能管理自己的会话；修改密码会撤销包括当前设备在内的全部会话。要求管理员先登记 MFA 时，这些安全设置仍允许撤销本人设备；单设备 DELETE 继续检查 CSRF、实时会话及归属，不开放业务接口。
- **账号异步响应**：网页按登录代次接纳资料更新、MFA 状态回读、提示及退出回调。退出后重新登录，即使是同一账号，也不会接纳旧登录发出的账号回写；同次登录的用户资料还按版本单调更新，拒绝旧版本回退。修改密码等待响应期间，退出入口和新的密码提交互斥，切换页面再返回仍保持；响应完成后再退出，失败则释放操作锁并保留当前页输入。
- **频率限制与失败响应**：注册、登录、密码与授权操作限流由数据库原子计数，超过返回 429。另对账号写请求或未登录来源设置每分钟 120 次的上限。为避免恶意灌日志，同一账号每分钟最多记录 10 条拒绝事件。数据库短时忙碌返回 503 和 `Retry-After`，不把抢锁失败伪装成预约成功。
- **认证资源与异常隔离**：所有密码散列及验证共用每进程最多 2 个运行任务、16 个等待任务的队列；超出返回 503，任务失败仍释放名额。短信验证码及两步验证的五次尝试上限在数据库原子计数或事务内执行，并在消费前重新检查有效期与凭据状态，适用于共享同一本地数据库的多个进程。畸形请求地址返回 400，错误日志使用已解析的安全路径，避免错误处理再次抛错退出服务。

当前 Docker 版适用于单机 SQLite 或多个进程共享**同一个本地数据库文件**。不支持把数据卷复制成多台服务器的独立数据库后继续保证全局互斥，也不建议使用网络文件系统共享 SQLite。多服务器部署需改用支持集中事务的数据库。

升级前请先备份数据库。启动会执行保留业务数据的增量迁移；旧版已有管理员原本拥有完整管理能力，因此保留完整权限并迁移为超级管理员。新建工作人员只能获得明确勾选的权限。

数据库版本现为 7。旧版预约、图片、账号和日志保留，取消信息采用新增字段；取消记录仍关联原申请。程序拒绝高于自身支持版本的数据库。升级后不要直接切回不理解取消状态的旧镜像；回滚必须先停服务、备份当前数据，再使用相匹配的旧数据库与程序版本。升级前发出的手机号绑定验证码须重新获取。

费用核对使用独立 `payments.manage` 权限；金额以整数分保存，企业只能提交流水，不能确认收款或退款。电话、费用和工作日历写入均在事务内重新鉴权并检查最新版本。取消时未核清付款进入核款或作废流程，不自动退款或把费用移到改期申请。详见[办理与费用规则](casework.md)。

纯财务的列表、详情和写入统一限制为已批准或已有费用记录的申请，不能借办理接口读取无费用的待审、退回企业资料。取消后作废费用发现实际到账，以及已完成电话登记的纠正，均须使用显式操作、最新版本和必填依据，保留审计；不允许企业自报到账或无痕覆盖联系结果。

## 验证码与快捷注册

注册和登录 API 调用需先获取 `/api/auth/captcha`，保留响应的 `hust_captcha` Cookie，将返回的 `id` 作为 `captchaId`、用户输入作为 `captcha` 一起提交。验证码答案只以摘要保存，响应不含明文答案。测试通过 `createApp` 的内部依赖注入生成固定测试图片；正式入口及环境变量没有免验证码开关。

验证码 PNG 渲染使用独立的进程内受限队列，最多 2 项运行、16 项等待，超出返回 503 和 `Retry-After`。渲染失败释放名额，失败或超限不写入新验证码；原有每 IP 60 次/10 分钟的限流继续生效。该队列限制本进程的待处理图片任务，不替代公网入口限流或网络防护。

同一网页内的验证码读取跨组件生命周期串行执行，先等待在途响应及其 Cookie 结算，再生成后继图片，防止首次无绑定请求的迟到 Cookie 使当前图片失效。尚未发送且已过时的请求跳过，失败不会阻断后续换图。服务端仍按浏览器 Cookie 绑定及单次消费校验；该前端协调不覆盖其他标签页的独立请求。

短信发送路由和真实短信/语音适配器先检查号码必须为字符串，再校验格式；非法类型在外发前拒绝，不消费通信服务或写入验证码记录。

邮箱是登录名，**本版不验证邮箱所有权**。手机号可在账号设置中通过短信验证码及当前密码绑定，绑定后可用于快捷登录与本人选择的结果通知；资料中的联系电话不自动视为已验证号码。首次短信、QQ/微信验证后，可补齐企业资料并创建企业账号；已有邮箱账号须先登录后绑定，不按第三方昵称或相同邮箱自动合并。注册凭据绑定当前浏览器、10 分钟过期且单次消费；并发重复提交只会创建一个企业账号，客户端不能指定管理员身份。审核结果以系统申请记录为准。

手机号绑定验证码同时关联发起绑定的账号，切换账号不能消费；密码验证完成后在写入事务内再次检查有效期、尝试次数和归属。快捷注册凭据过期时保留当前填写内容并提示重新验证。登录完成后，旧会话查询或旧账号请求的迟到响应不能覆盖新登录状态。

成功创建新登录会话时，统一撤销当前浏览器 Cookie 对应的旧会话，密码、短信、OAuth、MFA 完成和注册路径保持相同规则。其他设备会话保留；验证失败或仅进入 MFA 挑战不提前撤销当前身份。浏览器界面防迟到响应与服务端撤销旧令牌分别生效，不能互相替代。

已补齐现场实际摆放登记、保留旧预约的改期审批、图片完整解码、历史资料归档和管理员两步验证。短信、QQ/微信、自动电话、S3 与外部告警均有真实服务接口，但第三方账号申请、区域开通、域名回调与实际送达仍需使用自己的服务账号验收。测试注入的通信响应不代表真实运营商、QQ、微信或对象存储已接通。

备份验证密钥与快照配对；跨源写入检查来源、CSRF 和职责授权，认证与保存中的页面入口保持互斥。验证依据及当前边界见[质量说明](quality.md)。

## 两步验证与密钥

账号设置支持扫码绑定 TOTP 验证器，确认动态码后才启用，并显示 10 个一次性恢复码。登录先验证密码，再验证动态码或恢复码；验证码不可重放，挑战绑定当前浏览器、5 分钟有效、最多 5 次尝试。启用或关闭时撤销其他设备会话。Docker 默认 `REQUIRE_ADMIN_MFA=true`，未登记的管理员只能完成账号安全设置；现有安装升级后也需登记。

MFA 状态读取中及失败时分别显示“正在读取”和“状态待确认”，暂停按旧状态操作，并提供“重新读取验证状态”。启用成功后的读取或账号同步失败会保留本次恢复码；重试只读取及同步，不重新提交启用或重新生成恢复码。账号同步错误明确区分设置已保存与保存失败，关闭页面前仍须妥善保存恢复码。

MFA 验证还使用数据库中的账号级窗口：同一账号每 15 分钟最多 10 次尝试，跨来源、重新获取挑战和共享同一数据库的服务累计；密码正确或发出新挑战不重置额度。只有当前凭据有效且属于本浏览器的挑战才计数，错误验证码不会回滚次数；完整 MFA 成功后在同一事务内清除该账号计数。该限额提高第二因素抗猜测能力，也意味着密码已泄漏者可能耗尽该账号的短时验证额度，应同时处置密码泄漏。

密钥以 AES-256-GCM 加密保存。`APP_ENCRYPTION_KEY` 是可选的 64 位十六进制密钥；未设置时自动生成 `/app/data/.mfa-key`，不得删除、随意更换或提交到 Git。可用 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 在本机生成密钥。恢复码请离线保存。

备份及加密恢复会用配套密钥验证库内全部 MFA 密文的 GCM 认证标签，防止把等长但错误的密钥当成有效配对；轮换只计算通过校验的备份。该检查不输出明文，不验证真实企业身份，也不代替完整恢复演练。没有 MFA 表或记录的旧库仍可备份和恢复。

## 密码存储与图片处理

密码使用随机盐 scrypt 哈希；HttpOnly Cookie 会话令牌在数据库中仅保存摘要，默认有效期 7 天。认证写入检查来源与 CSRF。图片使用 sharp 完整解码、移除元数据并重新编码，限制见上表；过载可按原幂等标识重试。实际使用时请根据校方要求完成域名、HTTPS、备份、隐私告知与运维配置。

## 配置条件与已知边界

| 项目                   | 当前状态                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------- |
| HTTPS 与 Secure Cookie | TLS 由部署侧提供；`COOKIE_SECURE` 默认 `false`，HTTPS 正式环境须显式设置 `true`        |
| 管理员两步验证         | 示例配置及 Compose 默认 `REQUIRE_ADMIN_MFA=true`；不能据此断言任意手工启动环境也已启用 |
| 网络层防护             | 未内置 WAF、CDN 清洗或完整 DDoS 防护；应用限流和计算队列不能替代这些能力               |
| 邮箱和企业身份         | 邮箱仅作为登录名，尚未验证邮箱所有权；填写企业资料不等于核验企业真实性                 |
| 数据静态加密           | 普通 SQLite 业务库没有整体加密；密码为散列，MFA 秘密加密保存，异机备份另行加密         |
| 日志和存储权限         | 审计保存在数据库中，不是独立防篡改日志；拥有主机或数据库写权限的人仍能影响记录         |
| 备份和告警             | 本机备份可用不代表异机副本已建立；S3 和独立告警需配置凭据、接收方及恢复演练            |
| 外部身份和通信         | 短信、语音、QQ/微信的代码与协议测试不等于实际送达或授权资质已经验收                    |
| 多服务器运行           | 当前只支持单机或多个进程共享同一本地 SQLite，独立数据卷不能保证全局互斥                |

部署配置见[配置说明](configuration.md)，备份、恢复和独立监控见[运行维护](operations.md)与[外部接入](integrations.md)。现有自动测试覆盖权限、并发、凭据与恢复等边界，但不能据此认定不存在其他漏洞。
