# 界面合并核验

核验对象为合并提交 `1386d5e`：原主分支 `a375215` 与界面分支 `86910b3`。结论针对这次“采用校园界面、保留当前业务逻辑”的合并，不代表全部外部服务已经完成生产验收。

## 代码核对

- 合并提交具有两个父提交，界面分支已经进入主分支历史。
- 对后端、共享权限、依赖与请求层逐文件比较 Git 对象摘要，除已注明的静态类型支持外，文件与原主分支一致。
- `server/app.mjs` 仅增加 `.woff2` 与 `.txt` 的响应类型，供标题字体及授权文本使用；认证、鉴权、事务、数据表与迁移未改写。
- `src/api.js`、依赖清单及锁文件保持原主分支版本；App 的登录、会话、授权导航、请求失效保护和业务状态代码保持一致。
- 未引入 `preview.js`、身份切换入口、模拟 API 或浏览器本地业务存储。

## 界面与业务衔接

采用界面分支的校园配色、校名字样、本地标题字体、顶部导航及地图工具栏布局。保留独立工作台、验证码、MFA、首次快捷注册、审批、改期、现场登记、公告、授权和维护入口。

界面不是对旧分支源码的原样覆盖：工作台和现有功能按当前业务保留；弹窗继续使用 Radix，关闭后恢复触发按钮焦点；审批台为新页头调整空间，桌面可同时核对材料缩略图、冲突提示和审批操作。
