# 华中科技大学户外广场企业布展预约系统

第一版前后端实现：React 界面、Node.js 24 API、SQLite 数据库。账号、申请、设计图、审核、公告、场地安排和操作日志全部保存在服务端。不再使用身份切换、本机模拟申请或预置企业数据。

## Docker 启动

需要已启动的 Docker Desktop（Linux containers）或 Docker Engine + Compose。

1. 将 `.env.example` 复制为 `.env`：Windows 执行 `Copy-Item .env.example .env`，Linux/macOS 执行 `cp .env.example .env`。
2. 编辑 `.env`，设置管理员 `ADMIN_EMAIL` 和独立的 `ADMIN_PASSWORD`。密码需为 10–128 位并包含英文字母和数字。程序拒绝示例密码占位符。不要提交 `.env`。
3. 执行：

   ```powershell
   docker compose up --build -d
   ```

4. 访问 **http://localhost:8080**。管理员使用配置的邮箱和密码登录；企业在“登录 / 注册”中创建账号。

数据库和图片保存在 `app-data` 持久卷。重建镜像或 `docker compose down` 不清除数据。请勿使用删除卷的选项，除非已备份且确定要清空业务数据。在 `.env` 设置 `APP_PORT` 可更换访问端口。

```powershell
docker compose ps
docker compose logs --tail=100 app
```

公网运行请配置 HTTPS 反向代理，并设置 `COOKIE_SECURE=true`。默认 HTTP 配置供本机运行。正式服务推荐通过同一域名提供页面与 API。

## 账号与业务

- 企业：注册、登录、退出、资料维护、修改密码；修改密码后全部设备会话失效。
- 验证码：注册和登录均需填写 6 位数字 PNG 图片验证码；点击图片换一张。验证码由服务端生成并绑定浏览器，5 分钟过期，答错或验证成功即作废，不能重复使用；密码或网络错误后前端换图并保留其他输入。图片验证码不代表邮箱、手机号或企业身份已核验。
- 超级管理员：首次由服务端配置创建，拥有全部管理权限；通过“授权管理”创建工作人员并分配独立职责。普通注册只能获得企业身份，无法自行提升权限。
- 工作人员：按需授予企业申请审核、公告管理、场地开放管理、企业账号管理或日志查看权限。界面菜单和 API 使用同一权限定义；没有授权即使直接调用接口也会拒绝。
- 账号恢复：企业账号管理员只能管理企业。超级管理员可管理工作人员，受保护的超级管理员账号不能在网页中降权、停用或重置。临时密码仅显示一次，首次登录强制修改。
- 恢复密码：由管理员核验身份后重置。本版不发送验证邮件，也没有无验证的自助重置入口。
- 申报：最长 3 天（含起止日期）、29 个桁架位、3 MB 以内 JPG/PNG/WebP 设计图；待审核申请可撤回，未通过后可重新申报。
- 审核：查看完整申请与原图，通过/退回，退回原因必填；事务确保冲突时段不能重复通过。
- 取消：在申请详情中填写原因并明确确认，可取消仍生效的已通过预约，立即释放位置。企业只能取消自己的尚未开始或当日开始的预约；已开始但未结束的活动由有审核权限的管理员处理。已结束的预约保留历史，不允许通过取消改写历史。取消必须携带最新版本，不能恢复旧预约；改期需取消后重新申报。
- 审批台：管理员进入“企业申报审核”，默认左侧待办队列、右侧材料审阅。支持搜索、先到先审/最新优先排序、上一条/下一条、通过或退回后自动切换、快捷退回原因；桌面材料独立滚动，操作区始终保留在下方。
- 辅助核对：待审列表和详情提示日期过期、已通过预约冲突、暂停开放，以及同位重叠的其他待审数量。系统只核对日期与占用，设计图内容仍由有审核权限的人员确认。
- 批量处理：勾选本页记录后可批量通过/退回，操作前显示企业、位置、日期及冲突提示，并要求明确确认。统一退回原因必填；版本过期或冲突记录逐条跳过，页面列出成功数量和失败原因。服务端每批最多 50 条，当前列表每页 15 条，选项不跨搜索/分页保留。所有成功记录分别审计；若网络或权限中途异常，应刷新列表核对，重复处理不会覆盖终态。
- 隔离：企业只可查看自己的申请和图片；游客只看到公共场地信息与公告。
- 工作台：企业查看最近申请与审核意见，管理员直接处理待办，并查看最新公告；工作台不重复展示场地图。
- 场地查询：按 PDF 原图的五段位置提供日期查询、分布图/列表、区域筛选和放大查看。绿地边缘 6 个、B 座通道 4 个、A 座通道 4 个、东侧直线 7 个、南侧直线 8 个，共 29 个；已有预约的时段不能关闭。
- 地图比例：默认同时适配容器宽度和屏幕高度，保留原图 1350:1185 的纵横比；工具栏显示相对适配尺寸的缩放比例（75%–300%），支持一键适配、展开查看和 Escape 收起，放大后在地图内滚动。
- 公告：管理员在公告页直接填写标题和正文发布，可置顶，支持 Ctrl+Enter；发布失败保留输入。已发布内容支持编辑和删除，企业与游客公开阅读。
- 消息：工作台提供私有办理消息，显示审批结果、取消通知及待办提醒。提交申请会通知当前有审核权限的管理员；后台维护每天最多生成一次超过 24 小时的待办提醒。支持标记已读和分页，不发送邮件或短信。
- 日志：保留账号与业务操作，按日期、邮箱、操作代码或关联编号分页查询，可导出当前页 CSV；日期按北京时间解释。账号管理也改为服务端搜索与分页，不再截断为最近 1000 个账号。

## 并发、权限与会话规则

- **待审核不占位**：多家企业可以申请同一位置，但相同桁架在重叠日期内只能有一条生效预约。起止日期均计算在内；审核通过后占位，待审核申请可以撤回。
- **数据库兜底**：SQLite 触发器同时约束已通过预约、暂停安排和同一企业重复待审核申请。审批、撤回、暂停与恢复均在写事务中完成，并在事务内重新读取状态与授权；多进程共享同一个数据库文件也不能重复占用。
- **重试防重复**：提交申请支持 `Idempotency-Key`，同一账号以同一标识重试相同内容会得到原申请编号，不会新增记录或重复审计。同一标识提交不同内容返回 409。前端失败重试自动复用标识，修改内容后生成新标识。
- 幂等记录有效期为 7 天，后台会清理更早的标识；7 天后旧标识不再保证返回原编号，预约状态、重复待办和占用约束仍继续有效。
- **过期页面保护**：申请详情含版本号，前端审核和撤回携带 `If-Match`。状态已变化时返回 409，详情会重新读取。公告编辑/删除及管理员授权必须携带最新 `If-Match`，缺失返回 428，版本冲突返回 409，避免覆盖他人修改。
- **写入时重新鉴权**：不能使用上传开始时缓存的身份决定最终写入权限。停用、密码重置、退出或授权收回后，已失效会话即使继续上传也不能完成写入。管理员不能审批自己提交的申请。
- **授权确认**：创建工作人员、调整授权需超级管理员再次填写自己的当前密码。收回或调整权限会撤销目标账号全部登录会话，重新登录后才使用新权限。授权变更记录包含操作者、目标和权限变更内容，拒绝越权请求也会记录。
- **会话管理**：“账号设置”可查看当前及其他有效登录设备，退出某个其他设备或一次退出其他设备。只能管理自己的会话；修改密码会撤销包括当前设备在内的全部会话。
- **频率限制与失败响应**：注册、登录、密码与授权操作限流由数据库原子计数，超过返回 429。另对账号写请求或未登录来源设置每分钟 120 次的上限。为避免恶意灌日志，同一账号每分钟最多记录 10 条拒绝事件。数据库短时忙碌返回 503 和 `Retry-After`，不把抢锁失败伪装成预约成功。

当前 Docker 版适用于单机 SQLite 或多个进程共享**同一个本地数据库文件**。不支持把数据卷复制成多台服务器的独立数据库后继续保证全局互斥，也不建议使用网络文件系统共享 SQLite。多服务器部署需改用支持集中事务的数据库。

升级前请先备份数据库。启动会执行保留业务数据的增量迁移；旧版已有管理员原本拥有完整管理能力，因此保留完整权限并迁移为超级管理员。新建工作人员只能获得明确勾选的权限。

数据库版本现为 3。旧版预约、图片、账号和日志保留，取消信息采用新增字段；取消记录仍关联原申请。程序拒绝高于自身支持版本的数据库。升级后不要直接切回不理解取消状态的旧镜像；回滚必须先停服务、备份当前数据，再使用相匹配的旧数据库与程序版本。

## 长期运行与维护

超级管理员可在“运行维护”查看数据库和磁盘检查、最近成功备份、维护失败信息及超时待办，并手动启动一次后台备份和清理。普通企业及工作人员不能使用维护 API。

- 服务启动约 10 秒后执行首次维护，随后每小时检查一次。默认约每 24 小时备份，保留最近 14 份自动备份；`BACKUP_INTERVAL_HOURS`、`BACKUP_KEEP` 可调整，间隔设为 0 仅关闭自动备份，仍进行清理和手动备份。
- 备份在独立 Node 进程中执行，先写 `.part` 文件，完成 `PRAGMA quick_check` 后才改名为正式备份，并记录成功时间。只轮换本程序生成的 `auto-*.sqlite`，保留数量最少为 2；不会轮换人工命名的备份。失败保留诊断，并输出结构化错误日志。
- 默认目录 `/app/data/backups` 随 Docker 数据卷保留。**这仍是本机备份**，请通过运维任务复制到异机或其他独立存储；程序尚未配置异机上传和外部告警接收方。
- 定期清理过期验证码、过期会话、过期超过一天的限流记录、超过 7 天的幂等标识，以及超过 180 天的已读消息。不会自动删除申请、设计图、账号或审计日志。
- 设计图仍存于 SQLite；单个企业累计设计图限制为 200 MB，超过后需联系管理员制定归档方案。磁盘可用空间低于 `MIN_FREE_DISK_MB`（默认 256 MB）时，健康检查失败并阻止继续提交申请；不能代替磁盘容量规划。
- `/api/health` 检查数据库写入能力及磁盘空间，异常返回 503，不公开内部路径。反向代理或外部监控可检测这个地址；Docker Compose 的应用日志限制为每份 10 MB、最多 3 份。健康失败不会自动等同于完成修复，需要维护人员处理。
- 异常请求日志含 `X-Request-ID` 对应编号，方便定位；不输出请求正文和密码。界面中的维护状态与站内消息不能代替独立于应用的故障告警。

反向代理部署时，将 **直接连接应用、且确实由你控制的代理 IP** 填入 `TRUSTED_PROXY_IPS`（逗号分隔），代理应正确覆盖或追加 `X-Forwarded-For`。程序从右向左跳过可信代理，取第一个非可信地址；未配置时忽略所有转发头。不要信任任意用户能控制的代理或整个公网，否则会破坏限流。代理容器更换 IP 后，应同步更新配置。

注册和登录 API 调用需先获取 `/api/auth/captcha`，保留响应的 `hust_captcha` Cookie，将返回的 `id` 作为 `captchaId`、用户输入作为 `captcha` 一起提交。验证码答案只以摘要保存，响应不含明文答案。测试通过 `createApp` 的内部依赖注入生成固定测试图片；正式入口及环境变量没有免验证码开关。

邮箱是登录名，**本版不验证邮箱所有权**。手机号用于人工联系，尚未接入短信、QQ/微信授权或自动电话通知。审核结果以系统申请记录为准。

场地底图来自需求 PDF 第 11 页的原图区域（第 26 页同图），以 1350×1185 像素保存于 `src/assets/venue-plan.png`。交互坐标逐个对齐原图桁架，位于 `src/venue-layout.js`；不再重新编造布局或套用 9/10/10 分区。A 座、B 座是建筑名，原图未提供桁架编号，页面改用中性的 01–29 号作为系统编号，数据库 slot 主键保持不变，已有申请或暂停安排仍保留关联。具体位置以现场为准。

## 本地开发

Node.js **24 或更高版本**，数据库使用内置 `node:sqlite`。先配置 `.env`，然后：

```powershell
npm ci
npm run dev
```

前端：http://127.0.0.1:5173 ，API：http://127.0.0.1:3001 。开发时 Vite 代理 `/api`。如果端口被旧服务占用，请先停止旧进程。

编译并运行完整服务：

```powershell
npm run build
npm start
```

访问 http://localhost:3001 。`npm run preview` 仅预览静态页面，不提供账号 API。

## 管理员恢复与备份

管理员在首次启动时创建，后续更改环境变量不会自动覆盖已设置的密码。忘记管理员密码时，先修改 `.env` 的管理员配置，再显式执行：

```powershell
docker compose run --rm app node server/admin.mjs
```

该操作更新管理员密码并撤销其全部会话，不会把已注册企业提升为管理员。非 Docker 环境执行 `npm run admin:recover`。

在线一致性备份：

```powershell
docker compose exec app node server/backup.mjs /app/data/backups/manual.sqlite
docker compose cp app:/app/data/backups/manual.sqlite ./backup.sqlite
```

备份使用 SQLite `VACUUM INTO`，包含账号、申请和图片。目标文件必须尚不存在，每次备份请更换文件名。不要仅复制运行中的 SQLite 主文件，WAL 中可能仍有未合并数据。

恢复前先停止应用并备份原卷。由运维人员通过临时容器替换卷内数据库，并处理相应 WAL/SHM 文件后再启动。不要将任何业务数据库提交到仓库。

## GitHub Pages

https://crystalclear9.github.io/OutdoorsWeb/ 保留为静态前端入口。**Pages 不能运行 Node.js API 或数据库，无法独立提供真实账号服务。** 未连接后端时，页面明确提示、禁用申请提交，不显示模拟占用数据。账号及业务操作请使用 Docker 完整服务地址。

`npm run build` 生成 `dist/`，并将编译后的 `index.html` 和 `assets/` 同步至仓库根目录，适配目前 `main / (root)` 的 Pages 发布设置。源入口为 `src/index.html`，静态资源使用相对路径，兼容 `/OutdoorsWeb/`。

`VITE_API_BASE_URL` 可在编译时指定 API 地址，但推荐 Docker 同域运行。会话 Cookie 使用 SameSite=Lax，不能把跨站 Pages + API 直接视为正式同域服务。

## 验证

```powershell
npm run build
npm test
```

接口测试覆盖验证码过期/错误/跨浏览器使用/并发重放、代理来源识别、注册登录与权限、跨账号隔离、独立进程竞争审批、取消释放位置、通知隔离、日志分页、备份恢复、清理边界、维护失败和健康检查等。备份测试会将生成的备份复制为独立数据库，检查账号、申请和图片恢复。浏览器测试覆盖真实跨账号申报审批、验证码交互、取消预约、通知、维护界面、日志导出、手机端和 Pages 的未连接状态。

浏览器测试使用独立临时数据库，不写入正式数据库。默认使用本机 Edge。其他系统可设置 `PLAYWRIGHT_CHANNEL=chromium` 并先执行 `npx playwright install chromium`。

## 项目结构

- `src/`：React 界面，Radix Dialog 提供焦点和键盘交互。
- `server/`：HTTP API、SQLite、密码与会话、备份和管理员恢复。
- `shared/permissions.js`：前后端共用的业务权限定义。
- `server/tests/`：接口与权限测试。
- `tests/`：浏览器和静态发布测试。
- `Dockerfile`、`compose.yaml`：非 root 容器、健康检查、持久卷。

密码使用随机盐 scrypt 哈希；HttpOnly Cookie 会话令牌在数据库中仅保存摘要。认证写入检查来源与 CSRF。登录和注册设有频率限制，图片检查大小、类型和文件头。实际使用时请根据校方要求完成域名、HTTPS、备份、隐私告知与运维配置。
