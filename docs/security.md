# 权限、并发与账号安全

## 并发、权限与会话规则

- **待审核不占位**：多家企业可以申请同一位置，但相同桁架在重叠日期内只能有一条生效预约。起止日期均计算在内；审核通过后占位，待审核申请可以撤回。
- **数据库兜底**：SQLite 触发器同时约束已通过预约、暂停安排和同一企业重复待审核申请。审批、撤回、暂停与恢复均在写事务中完成，并在事务内重新读取状态与授权；多进程共享同一个数据库文件也不能重复占用。
- **重试防重复**：提交申请支持 `Idempotency-Key`，同一账号以同一标识重试相同内容会得到原申请编号，不会新增记录或重复审计。同一标识提交不同内容返回 409。前端失败重试自动复用标识，修改内容后生成新标识。
- 幂等记录有效期为 7 天，后台会清理更早的标识；7 天后旧标识不再保证返回原编号，预约状态、重复待办和占用约束仍继续有效。
- **过期页面保护**：申请详情含版本号，前端审核和撤回携带 `If-Match`。状态已变化时返回 409，详情会重新读取。公告编辑/删除及管理员授权必须携带最新 `If-Match`，缺失返回 428，版本冲突返回 409，避免覆盖他人修改。
- **写入时重新鉴权**：不能使用上传开始时缓存的身份决定最终写入权限。停用、密码重置、退出或授权收回后，已失效会话即使继续上传也不能完成写入。管理员不能审批自己提交的申请。
- **授权确认**：创建工作人员、调整授权需超级管理员再次填写自己的当前密码。收回或调整权限会撤销目标账号全部登录会话，重新登录后才使用新权限。授权变更记录包含操作者、目标和权限变更内容，拒绝越权请求也会记录。
- **会话管理**：“账号设置”可查看当前及其他有效登录设备，退出某个其他设备或一次退出其他设备。只能管理自己的会话；修改密码会撤销包括当前设备在内的全部会话。
- **频率限制与失败响应**：注册、登录、密码与授权操作限流由数据库原子计数，超过返回 429。另对账号写请求或未登录来源设置每分钟 120 次的上限。为避免恶意灌日志，同一账号每分钟最多记录 10 条拒绝事件。数据库短时忙碌返回 503 和 `Retry-After`，不把抢锁失败伪装成预约成功。
- **认证资源与异常隔离**：所有密码散列及验证共用每进程最多 2 个运行任务、16 个等待任务的队列；超出返回 503，任务失败仍释放名额。短信验证码及两步验证的五次尝试上限在数据库原子计数或事务内执行，并在消费前重新检查有效期与凭据状态，适用于共享同一本地数据库的多个进程。畸形请求地址返回 400，错误日志使用已解析的安全路径，避免错误处理再次抛错退出服务。

当前 Docker 版适用于单机 SQLite 或多个进程共享**同一个本地数据库文件**。不支持把数据卷复制成多台服务器的独立数据库后继续保证全局互斥，也不建议使用网络文件系统共享 SQLite。多服务器部署需改用支持集中事务的数据库。

升级前请先备份数据库。启动会执行保留业务数据的增量迁移；旧版已有管理员原本拥有完整管理能力，因此保留完整权限并迁移为超级管理员。新建工作人员只能获得明确勾选的权限。

数据库版本现为 6。旧版预约、图片、账号和日志保留，取消信息采用新增字段；取消记录仍关联原申请。程序拒绝高于自身支持版本的数据库。升级后不要直接切回不理解取消状态的旧镜像；回滚必须先停服务、备份当前数据，再使用相匹配的旧数据库与程序版本。升级前发出的手机号绑定验证码须重新获取。

## 验证码与快捷注册

注册和登录 API 调用需先获取 `/api/auth/captcha`，保留响应的 `hust_captcha` Cookie，将返回的 `id` 作为 `captchaId`、用户输入作为 `captcha` 一起提交。验证码答案只以摘要保存，响应不含明文答案。测试通过 `createApp` 的内部依赖注入生成固定测试图片；正式入口及环境变量没有免验证码开关。

邮箱是登录名，**本版不验证邮箱所有权**。手机号可在账号设置中通过短信验证码及当前密码绑定，绑定后可用于快捷登录与本人选择的结果通知；资料中的联系电话不自动视为已验证号码。首次短信、QQ/微信验证后，可补齐企业资料并创建企业账号；已有邮箱账号须先登录后绑定，不按第三方昵称或相同邮箱自动合并。注册凭据绑定当前浏览器、10 分钟过期且单次消费；并发重复提交只会创建一个企业账号，客户端不能指定管理员身份。审核结果以系统申请记录为准。

手机号绑定验证码同时关联发起绑定的账号，切换账号不能消费；密码验证完成后在写入事务内再次检查有效期、尝试次数和归属。快捷注册凭据过期时保留当前填写内容并提示重新验证。登录完成后，旧会话查询或旧账号请求的迟到响应不能覆盖新登录状态。

已补齐现场实际摆放登记、保留旧预约的改期审批、图片完整解码、历史资料归档和管理员两步验证。短信、QQ/微信、自动电话、S3 与外部告警均有真实服务接口，但第三方账号申请、区域开通、域名回调与实际送达仍需使用自己的服务账号验收。测试注入的通信响应不代表真实运营商、QQ、微信或对象存储已接通。

## 两步验证与密钥

账号设置支持扫码绑定 TOTP 验证器，确认动态码后才启用，并显示 10 个一次性恢复码。登录先验证密码，再验证动态码或恢复码；验证码不可重放，挑战绑定当前浏览器、5 分钟有效、最多 5 次尝试。启用或关闭时撤销其他设备会话。Docker 默认 `REQUIRE_ADMIN_MFA=true`，未登记的管理员只能完成账号安全设置；现有安装升级后也需登记。

密钥以 AES-256-GCM 加密保存。`APP_ENCRYPTION_KEY` 是可选的 64 位十六进制密钥；未设置时自动生成 `/app/data/.mfa-key`，不得删除、随意更换或提交到 Git。可用 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 在本机生成密钥。恢复码请离线保存。

## 密码存储与图片处理

密码使用随机盐 scrypt 哈希；HttpOnly Cookie 会话令牌在数据库中仅保存摘要。认证写入检查来源与 CSRF。登录和注册设有频率限制，图片除文件头校验外，使用 sharp 完整解码，拒绝动画、最长边超过 10000 或超过 2000 万像素的图片；剥离元数据并重编码为无损 WebP，输出上限 6 MB。每进程最多同时解码 2 张、排队 16 张，超额返回 503，可按原幂等标识重试。实际使用时请根据校方要求完成域名、HTTPS、备份、隐私告知与运维配置。
