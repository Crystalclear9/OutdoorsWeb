# 电话跟进、工作日历与线下费用

登录后的“服务工作台”提供“通知与缴费办理”入口。企业只能查看自己的记录；有申请审核权限的工作人员登记结果电话；有独立 `payments.manage` 权限的财务人员处理费用。超级管理员拥有全部权限，已有普通工作人员不会自动获得财务权限。

用户已于 2026-10-22 确认保留“财务确认后通知企业”的流程：审批通过先形成财务待办，财务核定金额或免缴依据并发单后，企业才收到正式通知。这是已确认的业务设计，不是待补的自动收费功能。

“待跟进事项”只显示当前角色可以处理的任务：审核人员跟进审批及结果电话，财务跟进费用，兼有两种授权时合并显示。企业仍查看自己的完整办理进度。取消或批准改期时，若原费用已收款或待核款，会另行通知在职财务处理；重复请求不重复提醒。

普通审批通过、批量通过和改期新单批准时，系统在同一事务中向在职财务及超级管理员发送费用安排待办，点击可打开对应记录。退回或重复审批不制造待办。**审核通过不等于已发送正式缴费通知**：财务按实际收费依据核定金额或免缴后，才向企业发出正式通知，不会自动编造收费标准。

申请详情中展开“查看办理时限、电话跟进与费用记录”也能访问本申请记录。纯财务账号可使用独立办理页，不因此获得审批或设计图访问权限。

纯财务账号的办理列表和详情仅覆盖已批准申请或已有费用记录的申请；不能读取无费用的待审、退回申请资料。财务在工作台看到付款与取消核款消息，点击可直接定位对应申请，不必翻页查找。队列缩减导致当前页超出末页时自动回退。

## 一个工作日反馈

反馈时限按提交后的**下一个工作日同一北京时间**计算。例如周五 10:00 提交，默认周一 10:00 到期。默认工作日为周一至周五；节假日、调休上班和校内停办日由超级管理员在办理页底部的“维护工作日历”逐日维护，支持恢复默认。

系统不自动推测国家或学校日历。投入运行前须按本单位安排录入；可维护前后三年的日期。调整会影响已有记录的时限计算，变更包含版本检查及审计。

审批通过或退回后，审核人员可拨打详情中的联系电话，填写“未接通”或“已接通并告知审核结果”和核对说明。未审批的申请不能登记结果告知；未接通继续保留在待跟进队列。企业看到告知状态及时间，不读取内部联系说明。

误登记为已接通时，审核人员在原记录填写原因并显式纠正，恢复为需继续联系，重新进入待办。历史登记保留在审计中，不删除原联系次数；不能直接用普通登记覆盖已完成结果。工作日历首次读取失败可在原位置重试。

后台维护按工作日历检查未完成的结果电话，每天最多向当前审核人员发送一次超期提醒；已审批但尚未告知的申请仍计算超期。取消或撤回不继续催办。运行维护页显示同样口径的超期数量；保留的 `pendingOver24` 接口字段仅供旧调用方兼容。

实际拨号及告知结果需要工作人员核实。自动语音/短信使用现有外部通信配置，但服务商“已受理”不会自动标成电话已接通。系统支持办理时限管理，不能保证人工必然按时完成。

## 线下缴费闭环

系统不预设收费标准，也不直接扣款或连接在线支付网关。费用金额、收费依据、单位收款渠道与收款说明由有财务权限的人员依据实际规则逐单填写；金额按人民币整数分保存，单笔最高 100 万元。

1. 预约批准生效后，财务发出缴费通知，或填写依据后登记免缴。企业收到站内消息，可查看金额和收款说明。
2. 企业按正式收款说明在线下完成付款，再提交付款时间和交易流水。此时只是“流水待核对”。
3. 财务核对单位实际资金记录，填写依据并确认，才变为“已核实收款”。未核实的流水可退回企业补充，核实未收款的费用单可作废。
4. 修改金额前先作废未收款单，再用最新版本重新发出费用通知。已核实收款不能直接改价或作废；确已线下全额退款后填写退款流水并登记退款。

| 状态           | 后续办理                                                                   |
| -------------- | -------------------------------------------------------------------------- |
| 尚无费用通知   | 生效预约可由财务发出缴费或免缴通知                                         |
| 待缴费         | 企业提交流水；财务核实到账或作废未收款单                                   |
| 流水待核对     | 财务确认收款、退回补充或核实未收款后作废                                   |
| 已核实收款     | 保留入账记录；实际全额退款后登记退款                                       |
| 免缴           | 保留免缴依据                                                               |
| 已作废         | 不再催缴；原预约仍生效时可重新发出通知                                     |
| 取消后待核款   | 核实取消前提交的流水是否到账，到账后进入收款和退款流程；未到账则核实后作废 |
| 已登记全额退款 | 保留退款依据，不重复登记                                                   |

取消预约时，未提交流水的费用单自动作废；已提交流水的单据进入“取消后待核款”。已确认收款的原单保留，作为取消后的退款待办。费用不会自动转移到改期申请。企业应停止付款，不以系统作废状态作为银行未到账的证明。

原费用已作废、取消后才发现真实到账时，财务在原费用记录使用“登记取消后到账”，填写实际到账流水和核对依据。系统凭最新版本将原单登记为已核实收款并进入退款待办；后续实际全额退款后登记退款。企业和审核人员不能使用此操作，重复登记不会再次入账。

本版登记全额线下退款，不执行银行退款，不处理部分退款、税务发票或银行自动对账。财务保存前需核对真实资金记录；系统提交或重复点击不等于发生资金划转。

## 一致性与留痕

电话结果、费用状态和工作日历都在事务内重新鉴权并检查版本。并发确认收款只有一次能够成功；失败不能覆盖已保存结果。初次发费用通知同样检查预约实时有效性和是否已有费用单。

办理详情刷新失败时保留当前表单输入，并暂时禁止提交；点击重新读取，核对到最新记录后才恢复操作。刷新期间也不能提交旧版本。切换其他申请时不沿用上一条记录的数据。

通知、企业流水、核款、作废、退款、电话结果和日历变更记录在审计日志中。重新开单保留之前的审计记录。普通企业不能自报“已收款”，审核权限不替代财务权限，财务权限也不替代审核权限。

数据库结构升级到 **7**，保留原账号及申请，并为既有申请回填“尚未登记结果电话”；不能推测旧申请已完成电话告知。升级不会批量发送收费通知。升级前备份，回滚需恢复匹配的旧数据库和程序。

新增验证：`server/tests/casework.test.mjs` 覆盖日历、归属、角色隔离、并发状态迁移、取消核款及升级；`tests/casework.spec.js` 覆盖真实企业、管理员和独立财务的通知—付款流水—核款—电话—取消—退款操作及手机端。
